# 仅标注音符与连续重复去重设计

## 目标

1. 只为可信音符头生成简谱标注；谱号、行首调号、拍号、休止符、小节线、力度和反复记号等不标注。
2. 每个谱表行内，连续多个完全相同的音符事件只标注第一个。

## 连续相同的定义

事件按谱表行从左到右比较。完整特征由以下内容组成：

- 简谱数字；
- 八度点数；
- 升降号；
- 时值；
- 和弦中全部音符的上述特征。

只有完整特征一致才视为相同。休止符和小节线不打断连续关系；遇到不同音符事件后重新开始；切换到下一谱表行时重置。

## 实现

### 非音符过滤

采用保守策略，优先避免漏掉真实音符：

- 保留现有音符头形状校验；
- 继续排除明确的谱号、行首调号和拍号区域；
- 继续要求候选归属检测到的谱表；
- 不使用“每个实心音符必须检测到符干”的强制条件，因为复杂和弦、共用符干和较差扫描可能因此漏标。

无法明确判断的候选暂时保留，不通过不断叠加距离启发式来猜测。该策略不能保证消除所有外形接近音符头的符号，但不会为了少量误标大量删除真实音符。

### 连续事件去重

在 `build_chords` 完成后、渲染前，按 `Staff` 分组并按横坐标排序 `ChordEvent`。计算每个事件的规范化特征；若与同谱表前一个保留事件一致，则不传给渲染器。底层 `Page.noteheads` 和调试信息保持不变。

## 测试

- 谱号、休止符或拍号形状候选不生成标注事件；
- 现有明确符号过滤规则保持有效；
- 同数字但八度、升降号或时值不同，仍分别标注；
- 连续完全相同的单音只保留第一个；
- 连续完全相同的和弦只保留第一个；
- 不同事件之后再次出现相同事件时重新标注；
- 不同谱表行分别从第一个事件开始标注；
- 至少一张真实谱面图片端到端处理成功并生成可读取结果。

代码继续使用 OpenCV 和 NumPy，不接入大模型或外部 API。
